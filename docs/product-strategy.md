# Crawlume 产品策略

## 定位

Crawlume 是面向 AI Agent 的可信网页访问层：稳定读取、明确失败、用户授权、来源可追溯。

它不承诺“任何网站都能读”，不伪装第三方机器人，不自动破解验证码、登录或付费墙。

Crawlume 的付费核心不是多租户或企业管理功能，而是让用户以更低的单位有效结果成本，持续得到
正确、完整、足够新、可追溯的网页数据。产品总指标是 `Cost per Valid Artifact`；原始请求成功率、
页面吞吐和浏览器使用量只用于解释该指标。

## 用户与产品面

### 免费本地版

面向开发者、研究人员和 AI 重度用户：

- CLI、MCP。
- HTTP 与本机 Chrome。
- 用户主动创建的专用授权 Profile。
- 单页读取、站点 Map、Crawl、批量读取。
- 通过用户自建 SearXNG 提供搜索发现。
- 本地缓存、内容哈希和明确错误。

本地版承担获客、信任建立和真实使用反馈，不依赖外部付费 API。

### 付费抓取服务

用户购买的是稳定的 Web-to-Data 结果，以及免除浏览器、队列、抽取、重试和站点变化维护成本：

- 单页、批量和站点范围的托管抓取。
- 在成本预算内自动选择 Cache、HTTP、Browser、结构化数据源或站点 Adapter。
- Markdown 与版本化 JSON Schema 输出。
- 耐久任务、页级恢复、流式结果和明确部分失败。
- 经过独立真值验证的可靠性、错误成功率和单位有效结果成本。
- 按有效结果和高成本资源透明计量，而非出售“无限抓取”承诺。

早期服务只需要 API Key、用量和客户数据隔离。组织、SSO、RBAC、复杂控制台和多租户管理不是
爬虫核心，应在真实客户和交付需求证明价值后再做。

### ToC Pro

用户购买的是研究和监控结果，而不是“爬虫”：

- 浏览器插件，一键把当前页面交给 Agent。
- 定时监控和变化提醒。
- 项目、标签、全文搜索和引用存档。
- 跨设备同步和批量任务。
- 本地凭证，云端只运行用户明确提交的任务。

### 可选服务化与私有部署

当交付规模确有需要时，再增加：

- 托管 API、MCP Gateway、Webhook 和 SLA。
- API Key、额度、计量和最小客户隔离。
- 私有部署或客户环境内 Worker。
- 团队、SSO、账单等非核心管理面。

这些是交付和运营能力，不是 Crawlume 抓取可靠性的护城河，也不能排在 Benchmark、Planner、验证、
恢复和成本优化之前。

## 访问策略

| 页面状态 | 默认行为 |
|---|---|
| 公开且允许 | HTTP 读取 |
| JavaScript 壳或正文不完整 | 使用真实 Chrome |
| 用户自己的登录内容 | 使用专用授权 Profile |
| 需要机器可读许可或付费 | 等待明确授权或预算确认 |
| robots 禁止 | 停止 |
| 401、402、403 | 明确失败，不伪装其他机器人 |
| 429、临时 5xx | 有界退避，不旋转身份规避限制 |

## 产品护城河

- 分层真值 Corpus、错误成功检测和可复现 Reliability Benchmark。
- 真实运行积累的失败类别、Provider 路径收益和成本数据。
- 在 Cache、HTTP、Browser、结构化源和 Adapter 间选择的可解释 Access Planner。
- 站点 Adapter 的稳定 Schema、Fixture、Live Canary 和改版修复速度。
- 访问结果带证据，不只返回一段 Markdown。
- 本地与托管执行可组合，授权 Profile 默认不进入共享索引。
- 统一权限和许可策略，而非把风险推给每个 Agent。

## 商业原则

- 基础本地读取免费。
- 托管服务对有效页面、耐久 Crawl、浏览器时间、监控和高价值 Adapter 收费。
- 计费优先与有效结果对齐；失败、策略停止和昂贵可选路径必须透明。
- 高成本路径必须独立计量，不能销售不可持续的无限套餐。
- 不以绕过付费墙、验证码或站点明确封禁作为卖点。
