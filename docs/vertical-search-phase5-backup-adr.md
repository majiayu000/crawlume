# 垂直搜索 Phase 5 SQLite 备份与恢复 ADR

状态：Implemented

日期：2026-08-31

关联文档：[二期数据层 ADR](./vertical-search-phase2-adr.md)、
[Phase 5 备份完成账本](./vertical-search-phase5-backup-ledger.md)

## 1. 目标

本阶段只为文件型 SQLite 数据库补齐一个可演练的本地安全闭环：从仍在运行的 WAL 数据库创建一致
备份，对备份执行 SQLite 完整性检查并生成内容校验元数据，再把已验证备份恢复到一个不存在的新路径。

## 2. 决策

- 使用 Node.js `node:sqlite` 的 online backup API，从独立只读连接读取源数据库，因此已提交但尚未
  checkpoint 的 WAL 内容会进入一致快照。
- 备份先写入目标目录内的随机临时文件，完整性检查通过后用不可覆盖的硬链接原子发布，再删除临时
  文件。目标已存在时显式失败。
- 元数据版本固定为 `crawlume-sqlite-backup-v1`，包含创建时间、`integrity_check` 结果、SQLite 页数、
  文件字节数和 SHA-256。校验会重新计算这些事实，不信任调用方提供的声明。
- 恢复先验证备份和元数据，再复制到目标目录内的随机临时文件；临时副本再次校验后，以同样的
  不可覆盖原子发布方式写入新目标。
- 所有失败路径清理任务创建的临时文件；不会删除或覆盖源数据库、备份或既有恢复目标。

## 3. 边界

- API 只接受本地文件型 SQLite，不接受 `:memory:`。
- 元数据由 API 返回给调用方；本阶段不增加 manifest 存储、云存储、加密/KMS、调度器、CLI、MCP、
  多副本编排或真实用户数据库操作。
- 本阶段不修改现有 schema，也不把备份能力接入应用启动流程。

## 4. 验收

- WAL 中已提交数据进入一致备份。
- 损坏备份或与元数据不一致的备份被拒绝。
- 备份和恢复均拒绝既有目标。
- 恢复数据库通过完整性检查，且关键数据表可读。
- 聚焦测试、相关 SQLite 回归、类型检查、构建和 Patch Guard 完成。
